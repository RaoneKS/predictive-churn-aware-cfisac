## Fairness and reporting rules

1. Use matched random seeds, topology, mobility traces, duration, bandwidth, power budget, and antenna/AP counts where the original algorithm permits it.
2. Preserve each paper's required feasibility constraints. Also report common metrics computed from the same evaluation model, and native metrics separately.
3. Each method must have a provenance label: `faithful_reproduction`, `compatible_reimplementation`, or `paper_inspired_proxy`. Never label a proxy as the published method itself.
4. Report mean rate, 5th-percentile rate, sensing metric, QoS/tracking violations, energy/fronthaul, handovers/reconfigurations, runtime, and feasibility only where definitions are implemented and valid. No invented SINR/MASR metrics.
5. For 30 graphs, use 10 metrics with three views each only after the data has been generated: time trajectory, paired-seed summary, and seed distribution. The proposed method must be visually identifiable in each relevant plot.
6. CSVs must retain seed, method/provenance, configuration, metric definition, and run identifier. Include a manifest with code commit and exact configuration.
7. Do not paste numerical values from papers into locally simulated plots as if they were same-condition experimental observations. If paper-reported results are shown, place them in a separate literature table/figure with source and model differences clearly stated.
8. Keep unfavorable outcomes and all previous result folders. New experiments use a new output path and refuse to overwrite it.
